# [プロジェクト名] Development Log

## Purpose

このドキュメントは、開発タスクについて、実施前の計画と実施後の結果をタスクID単位で記録する履歴である。

プロダクト要件、設計、アーキテクチャ、テスト条件、タスクの現在状態を定義するものではない。Single Source of Truthは、それぞれの担当ドキュメントとする。

## Recording Rules

- 1つのタスクIDを1つの記録単位として扱う
- 同じタスクを複数回実施した場合は、同じタスクIDの下に実行記録を追加する
- 実施前に計画を記録し、実施後に結果を追記する
- 計画との差分（重要なものを中心に）、テスト結果、残課題、証拠を簡潔に記録する
- 合意済み範囲内の実施前計画・結果の記録そのものにユーザー承認は不要。記録後も承認不要な作業を継続する
- 変更予定ファイルの事前列挙は任意とし、実際の主な変更箇所を結果に記録する
- 通常の実装記録は簡潔にし、重要な技術判断・問題・計画との差分では理由と影響を詳しく残す
- タスクの現在状態は`tasks.md`のみで管理し、このログで二重管理しない
- 並列開発時、各担当は実施結果・テスト結果・重要な判断・残課題・証拠（コミットSHA等）を統合担当へ引き渡す。共有のこのログへの反映は統合担当が行い、同一ファイルの並行編集を避ける
- コマンドの逐次的な実行ログは記録しない
- 仕様判断やエスカレーションが発生した場合は、その内容と決定を記録する

## Entry Template

```md
## [TASK-ID]：[タスク名]

### 実行記録 1

#### 実施前の計画

- 実施日：YYYY-MM-DD
- 目的・対象範囲：
- 実装方針・参照設計：
- 完了条件・対応テストID：
- 懸念・未決定事項：
- 変更予定ファイル（必要な場合）：

#### 実施後の結果

- 実施内容・主な変更ファイル：
- テストID・結果：
- 計画との重要な差分：
- 技術的判断と理由（重要な場合）：
- 残課題：
- 証拠（日時・CI URL・ログ・コミットSHA等）：
```
